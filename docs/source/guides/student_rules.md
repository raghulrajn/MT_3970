# Student Rules

The training pipeline is built on [PyTorch Lightning](https://lightning.ai/docs/pytorch/stable/) - you focus on your model architecture, Lightning handles the rest.

## What You CAN Modify

### Your Model

Create your model by copying the example:

```bash
cp src/models/dummy_model.py src/models/<your_model_name>.py
cp configs/model/dummy.yaml configs/model/<your_model_name>.yaml
```

Update `class_path` in your config to point to your model class:

```yaml
name: <your_model_name>
class_path: src.models.your_model_name.YourModelClass
```

You have complete freedom over architecture, layers, loss functions, and preprocessing.

### Notebooks

Use `notebooks/` for exploratory data analysis. **Figures that go into
your thesis must come from `scripts/make_figures.py`**, not from
notebooks - see the [Submission](./submission.md) guide.

## What You MUST NOT Modify

These files ensure fair comparison and reproducibility. Contact your supervisor if you need changes.

```
src/models/base_model.py        # Base class interface
src/models/dummy_model.py       # Reference implementation
src/metrics/                    # All metric implementations
src/data/                       # Data loading utilities
src/utils/                      # Utility functions
evaluate.py                     # Evaluation script
configs/dataset/                # Dataset configurations
configs/config.yaml             # Main config (except student info)
```

## Reproducibility Rules

Your results must reproduce **in a fresh sandbox**. Concretely:

1. Every dependency is recorded: `uv add <package>`, never a bare
   `pip install`. After `./sandbox.sh reset`, `uv sync --all-extras`
   must restore your full environment.
2. Your reported metrics come from a **registered** model
   (`evaluate.py --register`) - the submission tests reload it and
   recompute them.
3. Every thesis figure is generated by `scripts/make_figures.py`.

The check before every meeting and at submission:

```bash
./sandbox.sh reset && ./sandbox.sh start && ./sandbox.sh shell
uv sync --all-extras --frozen
uv run pytest tests/test_submission.py -v -m "not slow"
```

## Training and Evaluation

See the [Experiments](./experiments.md) guide for detailed commands. The essential workflow:

```bash
# Train
uv run main.py model=<your_model> dataset=ddacs

# Evaluate and register your best model
uv run evaluate.py --run_id <run_id> --datasets all --register

# Validate submission
uv run pytest tests/test_submission.py -v -m "not slow"
```
